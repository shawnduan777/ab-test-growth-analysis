# 基于 A/B Test 的个性化推荐模块增长分析

## 1. 项目简介

本项目通过模拟电商 App 新用户实验，评估在首页增加个性化商品推荐模块后，是否能够提升用户转化率及业务表现。

实验设置两个用户组：

- **对照组（A 组）**：使用现有首页。
- **实验组（B 组）**：在首页增加个性化商品推荐模块。

项目围绕增长分析的完整流程展开，包括实验设计、用户行为漏斗、统计假设检验、留存分析、收入与贡献利润分析，以及退款率等业务护栏指标。

> **声明：** 本项目为个人作品集项目，使用模拟数据进行分析。所有实验结果仅用于展示分析方法，不代表真实企业的业务表现或实际实验效果。

## 2. 业务问题

本项目主要回答以下问题：

1. 个性化推荐模块能否提升新用户注册后 7 日内的首单转化率？
2. 推荐模块主要影响用户行为漏斗中的哪个环节？
3. 转化率的变化是否伴随着收入和贡献利润的提升？
4. 推荐模块是否可能带来退款率上升等潜在负面影响？

## 3. 实验设计

| 项目 | 设定 |
|---|---|
| 实验对象 | 电商 App 新注册用户 |
| 实验单位 | 用户 |
| 对照组 | 现有首页 |
| 实验组 | 增加个性化推荐模块的首页 |
| 分组比例 | 1:1 |
| 总样本量 | 约 26,000 人 |
| 主指标 | 注册后 7 日内首单转化率 |
| 显著性水平 | 5%，双侧检验 |
| 目标统计功效 | 80% |
| 最小可检测效应（MDE） | 1 个百分点 |

样本量规划以 8% 的基线转化率和 9% 的目标转化率为假设，即希望检测到 1 个百分点的绝对提升。在双侧显著性水平为 5%、统计功效为 80%、两组等比例分配的条件下，计划样本量约为每组 13,000 人。

以上均为本项目的实验设计假设，并非真实行业基准。实际实验结果不预设为达到目标提升幅度。

## 4. 技术栈

- **MySQL / SQL**：用户行为漏斗、留存、收入和贡献利润统计。
- **Python**：数据处理、统计检验和可视化。
- **pandas / NumPy**：数据清洗与分析。
- **SciPy / statsmodels**：统计推断与比例检验。
- **Matplotlib**：实验结果和业务指标可视化。
- **Jupyter Notebook**：组织数据生成、分析和结果展示流程。

## 5. 分析流程

### 5.1 模拟数据生成

构建用户表、行为事件表、订单表和用户活跃记录表，模拟新用户分组、首页曝光、商品点击、加购、支付、退款和后续活跃行为。

各数据表通过 `user_id` 关联，订单表另包含 `order_id`。模拟数据用于验证完整的分析流程，不用于推断真实用户行为规律。

### 5.2 SQL 指标统计

使用 MySQL 完成以下分析：

- **漏斗分析**：首页曝光、商品点击、加购和支付各阶段的用户数与转化率。
- **留存分析**：D1、D7 用户留存率。
- **收入分析**：总收入、每用户平均收入（ARPU）、客单价（AOV）等。
- **利润与退款分析**：总贡献利润、每用户贡献利润、退款订单率及退款金额率。

### 5.3 A/B Test 统计检验

以 7 日首单转化率作为主指标，比较实验组与对照组的转化率差异，并使用双侧比例检验、p 值和 95% 置信区间评估实验结果。

同时结合漏斗和业务指标进行解释，避免仅凭单一指标判断实验是否成功。

## 6. 核心结果

### 6.1 主指标：7 日首单转化率

| 指标 | 对照组 A | 实验组 B |
|---|---:|---:|
| 用户数 | 13,000 | 13,000 |
| 首单购买用户数 | 1,089 | 1,147 |
| 首单转化率 | 8.38% | 8.82% |

统计检验结果：

- **绝对提升：** 约 +0.45 个百分点。
- **相对提升：** 约 +5.33%。
- **z 统计量：** 约 1.283。
- **p 值：** 0.1995。
- **转化率差的 95% 置信区间：** 约 −0.24 至 +1.13 个百分点。

**结论：** 实验组的观测转化率高于对照组，但差异未达到 5% 显著性水平。目前没有充分的统计证据表明增加个性化推荐模块能够提升 7 日首单转化率。

### 6.2 用户行为漏斗

| 指标 | 对照组 A | 实验组 B |
|---|---:|---:|
| 点击率 | 40.42% | 43.18% |
| 点击后加购率 | 51.34% | 50.69% |
| 加购后支付率 | 40.36% | 40.30% |
| 整体首单转化率 | 8.38% | 8.82% |

**结论：** 实验组的点击率更高，表明推荐模块可能促进了用户点击商品；但点击后的加购率和加购后的支付率没有表现出相应改善。因此，点击行为的提升尚未转化为统计显著的整体首单转化提升。

点击率的差异需要结合相应的统计检验结果解释，不能仅凭描述性数据推断因果效果。

### 6.3 收入与贡献利润

| 指标 | 对照组 A | 实验组 B |
|---|---:|---:|
| 总收入 | 67,416.44 | 71,274.97 |
| 每用户平均收入（ARPU） | 5.19 | 5.48 |
| 客单价（AOV） | 61.91 | 62.14 |
| 总贡献利润 | 20,389.70 | 21,390.69 |
| 每用户贡献利润 | 1.57 | 1.65 |

**结论：** 实验组的收入和贡献利润观测值均高于对照组。不过，目前这些指标仅进行了描述性比较，尚未完成相应的统计显著性检验，也未扣除推荐模块的实际开发和维护成本，因此不能据此确认推荐模块带来了显著的增量利润。

### 6.4 退款率护栏指标

| 指标 | 对照组 A | 实验组 B |
|---|---:|---:|
| 退款订单数 | 54 | 64 |
| 退款订单率 | 4.96% | 5.58% |
| 退款金额率 | 4.76% | 4.99% |

**结论：** 实验组的观测退款订单率较高，提示后续分析需要关注交易质量。但当前尚未对退款率差异进行统计检验，不能直接认定推荐模块导致退款率上升。

## 7. 业务建议

综合当前模拟实验结果，可以得出以下判断：

1. **点击行为有所改善：** 实验组点击率高于对照组，说明推荐模块可能提升了商品点击意愿。
2. **整体转化效果尚未得到统计验证：** 主指标差异不显著，不能直接宣布实验成功。
3. **业务价值仍需进一步验证：** 实验组的收入与贡献利润观测值更高，但尚未完成统计检验和完整成本核算。
4. **需要关注交易质量：** 实验组退款订单率的观测值较高，应进一步分析退款差异及其原因。

因此，当前不建议仅依据观测到的转化率和利润差异直接全面推广。更合理的后续方向是继续验证主指标，优化点击后的加购和支付环节，并在推广决策中纳入退款风险、开发维护成本和增量利润。

## 8. 项目局限性

- 所有数据均为模拟生成，无法代表真实业务中的用户行为或实际实验效果。
- 收入和贡献利润仅进行了描述性比较，尚未完成统计推断。
- 推荐模块的增量成本尚未通过真实业务数据核算。
- 模拟过程简化了真实用户行为、订单频率、退款机制和长期留存情况。
- 实际业务应用还需要考虑实验分流质量、样本比例异常、指标口径、数据质量和多重检验等问题。


## 9. 如何复现

1. 安装 `requirements.txt` 中列出的 Python 依赖。
2. 运行 `notebooks/01_generate_data.ipynb`，生成模拟数据。
3. 将生成的 CSV 数据导入 MySQL。
4. 根据 SQL 脚本执行环境配置数据库及数据表，运行 `sql/` 目录中的分析脚本。
5. 将 SQL 查询结果导出至 `results/` 目录。
6. 运行 `notebooks/02_ab_test_analysis.ipynb`，完成统计检验、结果分析和图表生成。

具体的 MySQL 安装、数据库创建和 CSV 导入方式可能因运行环境而异。
